# 从静态 Hero 准备入场素材

先看页面和已有文件，只询问无法从现有信息确定的内容：哪个场景入场、结束停在哪里、已有想法或视频是否满意。不要让小白填写技术配置表。

## 已有页面，只有截图

辨认截图中的主视觉与 HTML 文案。需要单独的场景原图作为视频终态；如果只有含 UI 的截图，先说明需获取或制作无 UI 场景图，不直接把整页截图交给视频模型。

## 先确定终态，再构思动作

用户没有想法时，围绕现有主体给出 2～3 个简短建议，例如自然走入归位、整理场景后停下、道具变化后主体入位。动作以保持身份和最终构图为前提，不强制人物或宠物。
默认可建议 5～6 秒，一个主动作加收势；具体时长还应服从用户平台的能力。

用户有想法时，整理成“整体过程 + 分段动作 + 最终停留”，指出会破坏终态的镜头或动作冲突，先确认关键创意再准备生成材料。
确认只用于需要用户选择的创意，不在每个技术步骤反复提问。

## 交付给用户的生成包

- 最终静态场景原图：明确文件和尺寸。
- 首帧：若需要首尾帧生成，列出或用已授权可用工具制作。没有生成工具时明确缺失，不假称已制作。
- 参考图：仅在主体身份或道具需要时提供，不强制额外 Logo。
- 完整视频提示词：动作顺序、固定内容、画幅、结尾稳定区。
- 回传说明：导出原始 MP4/WebM，勿额外加 UI、裁切或转场。

提示词示例结构（替换括号再交付，不把占位符交给生成器）：

以[终态图]为最终构图。固定镜头、画幅、主体比例、背景与光线。
[开场状态]，主体完成[一个主动作]，随后自然收势到[终态姿势]。
最后约 0.5～1 秒保持该构图稳定。不出现网页文字、导航、字幕或水印。
不在视频里做画面居中到侧边的缩放位移；该运动由网页控制。
保持[主体身份、道具几何、接触关系]一致，避免切镜头、闪白和淡出。

生成结果只能作为候选；首尾帧约束不能保证模型逐像素匹配。回传后检查真实尾部，再决定采用哪张接管图。
用户认可动作但接管有问题时，先排除坐标、颜色和底图版本，不直接要求重新生成。
