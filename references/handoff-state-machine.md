# 播放与交接时序

以确认的 handoffTime 为时间基准，它可能早于文件结尾。播放末尾回正、黑帧或多余静止段不应自动纳入展示。

    加载并解码 → 居中播放 → 尾部回位，同时文字出现 → 接管帧停留并淡出 → 可用

默认在接管前 1.15 秒开始回位，前 1 秒显示文字，淡出 160ms。短视频应压缩前段时间；这些参数可按用户节奏调整。

不得在 ended 后无条件再等一遍回位时长。模板按媒体进度计算回位位置，到接管点暂停并定位记录的帧，等待视频淡出和 UI 动画都结束后恢复交互。
有 requestVideoFrameCallback 时依据解码帧触发接管；不支持时按播放时间兜底，浏览器寻帧精度仍需视觉验收。

加载超时与播放无进展超时分开；较长视频只要继续播放，就不会被固定总时长中断。静态图和视频都准备好才显示视频层。

成功、跳过、失败均恢复静态页面并发出一次 hero-intro:ready，detail.reason 区分 completed、reduced-motion、already-played、user-skipped 或失败原因。
ready 表示页面已恢复可用，不等于视频成功播放或静态资源成功加载；资源失败还应报告 hero-intro:error。
组件销毁调用 destroy()，清理监听、计时与视频资源，不再发业务完成事件。
